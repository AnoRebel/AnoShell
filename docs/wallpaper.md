# Wallpapers

AnoShell's daemon, anod, applies wallpapers and everything that follows from
one, in this order:

1. **awww** shows the image, with the resize mode you chose
   (`background.resize`: `fit`, `crop`, `stretch` or `no`). The mode is recorded,
   so glass can sample exactly what is on screen.
2. **matugen** generates the Material colours from it, written where the shell
   reads them (`~/.local/state/anoshell/generated/colors.json`). The scheme is
   `appearance.colors.schemeType`; with several candidate colours,
   `appearance.colors.prefer` (default `saturation`) picks one.
3. **Your hooks** run one after another (`background.hooks`, below).
4. The change is announced: the shell updates, and your `hooks.wallpaperChanged`
   command runs.

### Colours per wallpaper

Light/dark, the scheme (Tonal spot, Vibrant, Expressive …) and the source
colour you pick in Settings → Appearance → Theme source (or with `scheme …` in
search) are remembered for the wallpaper on screen and come back with it
(`appearance.colors.perWallpaper`, on by default). Wallpapers without picks of
their own use the defaults, `appearance.colors.darkMode`, `schemeType` and
`prefer`:

- **Picks set the default** (`appearance.colors.pickSetsDefault`, on): your
  last pick is also the default, so new wallpapers look like the last one you
  tuned.
- Off: picks stay with their wallpaper, and the defaults get their own rows in
  Settings.

**Reset to defaults** in the same card forgets the current wallpaper's picks.
The picks are kept in `~/.local/state/anoshell/wallpaper-colors.json`.

With a different wallpaper on each monitor, **Colours from**
(`appearance.colors.from`) says which one sets the colours:

- **Last set** (`last`, default): the wallpaper you set most recently, on any
  monitor.
- **One monitor** (`monitor`): `appearance.colors.monitor`'s wallpaper; setting
  one on another monitor leaves the colours (and the hooks) alone. Rotation
  takes its colours from that monitor too.
- **Focused monitor** (`focused`): the colours follow focus. Palettes are
  cached per wallpaper and option set (`~/.cache/anoshell/colors/`), so a
  switch back is instant, but your hooks (pywal, app themes) run on every
  switch.

Picks always go to the wallpaper the colours currently follow; the card
names it.

### GTK apps

With **Colour GTK apps** on (Settings → Appearance → Theme source,
`appearance.theme.gtk`, on by default), anod keeps a marked block of palette
colours (libadwaita named colours, plus its CSS variables for GTK 4) at the
end of `~/.config/gtk-3.0/gtk.css` and `~/.config/gtk-4.0/gtk.css`; your own
rules outside the block are kept. GTK apps opened afterwards use it.

- A `gtk.css` that is a link to a theme's file becomes a file that `@import`s
  that theme, then the block.
- A `gtk.css` generated by iNiR is saved as `gtk.css.ano-backup` and replaced.
- Turning the switch off removes the block, puts a link back as it was and
  restores a backed-up file.

Folder icons are drawings in the icon theme, not CSS. AnoShell Tint, put on
at the first start (Settings → Displays → Icons), recolours your icon theme's
folders with the palette and switches GTK apps to it live.

### Qt apps

The `apps` step (`scripts/colors/applycolor.sh`) writes a palette colour
scheme for qt6ct (and qt5ct when it's set up) and points them at it
(`color_scheme_path`, `custom_palette`). **Qt apps** (Settings → Appearance →
Theme source, `appearance.theme.qt`) picks the style:

| Value | Style | When apps change colour |
|---|---|---|
| `"palette"` (default) | qt6ct's palette, with Fusion or the palette-drawn style you picked | live: qt6ct re-reads its config about 3 s after a change, palette and icon theme included |
| `"kvantum"` | a Kvantum theme in the palette (`~/.config/Kvantum/AnoColors`, shapes from KvArcDark) | when they next start |
| `"off"` | left alone | never |

It needs the qt6ct platform theme installed and `QT_QPA_PLATFORMTHEME=qt6ct`
in the session; without it Qt apps ignore all of this. Changing the style
takes effect when an app starts.

Kvantum can't follow a palette live: it draws widgets from an SVG whose
colours are baked in, and reads its theme when an app starts, so in
`"kvantum"` only text and background colours come from the palette.
For nicer shapes than Fusion that still follow live, KDE's Breeze style
(package `breeze`) uses the palette too: pick it in qt6ct (or set
`style=Breeze` in qt6ct.conf). In `"palette"` any style other than Kvantum
is kept; Kvantum or none becomes Fusion.

In the **Fixed** colour mode (Settings → Appearance → Theme source) step 3 is
skipped: the colours don't follow the wallpaper.

## Changing it

- The wallpaper picker (Super+W by default), or the bar's wallpaper action.
- From a terminal:

```sh
ano wallpaper set ~/Pictures/Wallpapers/forest.png
ano wallpaper set ~/Pictures/Wallpapers/forest.png --output HDMI-A-1 --mode light
ano wallpaper next      # the next rotation image, now
ano wallpaper status    # what's shown, and the rotation settings
```

## The wallpaper folder

`background.wallpaperDir` (Settings → Appearance → Wallpaper Picker, or the
picker's gear) is the one folder everything uses: the picker deals from it,
Wallhaven downloads land in it, rotation picks from it and `ano backup
create --add wallpapers` archives it. Empty (the default) means `Wallpapers` in your
Pictures folder (`XDG_PICTURES_DIR`, usually `~/Pictures/Wallpapers`).

```json
"background": { "wallpaperDir": "~/Pictures/hyprwallpapers" }
```

`background.randomize` changes the wallpaper on a timer, from the wallpaper
folder, or from `directory` if you give rotation its own:

```json
"background": {
  "randomize": { "enable": true, "interval": 300 }
}
```

Each screen gets a different image; colours and hooks follow the first one. Every
image is shown once before any repeats, and that holds across restarts.

If you used `awww_randomize_multi.sh` (or a similar script) from your compositor
config, it now fights anod's rotation. `ano doctor` warns while one runs, and
`ano wallpaper migrate` replaces it: it shows the lines it will change, asks,
backs the files up, comments the lines out, and turns rotation on with the same
folder and interval.

## Hooks

`background.hooks` is a list. Each hook is a command (an argument list, never a
shell string) with:

| Key | Meaning |
|---|---|
| `name` | shown in logs and in `ano wallpaper set`'s report |
| `enable` | `false` skips it |
| `command` | the program and its arguments; `{image}` (for a video wallpaper, a still frame of it), `{mode}` (`dark`/`light`) and `{colors}` (the colours file) are filled in |
| `timeoutSeconds` | killed after this long (default 20) |
| `builtin` | `"cava"` instead of a command: recolours cava from pywal and asks it to reload |

A hook that isn't installed is skipped (and says so). Hooks also get
`ANO_WALLPAPER`, `ANO_THEME_MODE` and `ANO_COLORS` in their environment.

The defaults reproduce the usual chain:

```json
"hooks": [
  { "name": "pywal", "enable": true, "command": ["wal", "-i", "{image}", "-n", "-q"], "timeoutSeconds": 30 },
  { "name": "swaync", "enable": true, "command": ["swaync-client", "--reload-css"] },
  { "name": "apps", "enable": true, "command": ["~/.config/quickshell/ano/scripts/colors/applycolor.sh", "--mode", "{mode}"], "timeoutSeconds": 30 },
  { "name": "cava", "enable": true, "builtin": "cava" },
  { "name": "themes", "enable": true, "command": ["~/.config/awww/scripts/awww_generate_themes.sh"], "timeoutSeconds": 30 }
]
```

### Example: your own hook

Add an entry to the list in `~/.config/anoshell/config.json`. This one tells
you which wallpaper was applied:

```json
{ "name": "notify", "enable": true, "command": ["notify-send", "Wallpaper", "{image}"], "timeoutSeconds": 5 }
```

Run `ano wallpaper set …` and the report lists `notify` with `"ok": true`, or
why it was skipped.

## Video wallpapers

awww shows stills and GIFs, so with it the picker lists no videos and anod
refuses them. For video, switch to the shell-drawn background
(experimental): Settings → Appearance → Wallpaper engine, or

```json
"background": { "engine": "shell" }
```

The shell then draws the wallpaper itself, with fade, wipe or grow transitions
(`background.transition`). Colours and hooks use a still frame of a video.
One video decodes on one screen at a time — the
focused one (`background.video.allScreens: true` decodes on every screen, at
that many times the cost); the other screens show a still of it. Decoding
pauses while a maximised or fullscreen window covers the screen. Glass doesn't
refract a video wallpaper.

Cost, measured on a 1080p H.264 loop: a still costs nothing once drawn; a
playing video costs about 11% of one CPU core; covered, about 2%.

## Colours of every wallpaper

anod keeps a cache of each wallpaper's main colour and brightness (keyed by
file, size and modification time), so the picker can sort by colour and glass
can keep text readable. A second look at an unchanged folder costs nothing.
